# OCTAVE의 역량 분류에서 정적 요구사항 판정까지

## 역량을 기준으로 과제 만들기

OCTAVE는 규칙·NPC·수치·입력·장면·렌더링·피드백·UI의 8개 역량을 정한다. 플레이어 요청, 상용 게임의 메커니즘, 전문가 설계에서 과제를 모으고 역량 범위를 고려해 180개를 선택한다. PC와 모바일 웹은 수집 단계부터 다른 트랙이다.

요구사항은 두 층으로 나뉜다.

| 구분 | 확인할 내용 |
| --- | --- |
| Completeness | 공개 명세의 핵심 기능과 관찰 가능한 결과 |
| Richness | 생성 프롬프트에 쓰지 않은 시스템 연결·경계 조건 |

전문가는 1,800개 요구사항의 판정 기준을 검토했다.

## 코드 판정과 사람의 조작 결과

평가기는 먼저 진입 파일과 실행 경로를 정적으로 검사하고, 이어 각 요구사항의 입력·상태 갱신·출력 근거를 찾는다. 실행 가능성도 코드에서 판단하며 실제 실행 검사는 아니다. 제한된 사람 대조에서는 사람이 충족했다고 본 항목을 평가기가 실패로 분류한 경우가 주된 불일치였다. 같은 모델의 생성·평가 결과도 별도로 해석해야 한다.

## 전체 점수에서 실제 오류로

후반의 실패 사례는 공유 자원과 종료 상태를 다룬다. 파이프 간 연결이 있어도 공유 유량 한도를 지키지 못하거나, 탈출과 포획이 같은 프레임에 발생할 때 종료 우선순위가 어긋날 수 있다. 기능의 존재와 시스템 간 일관성을 나눠 진단하는 이유다.

Kehang Li 외의 [OCTAVE v1](https://arxiv.org/html/2611.17681v1)(2026-11-13)에서 1·3~5장을 다시 읽었다. 생성·평가 실험은 재현하지 않았다.

# GARP의 캐릭터 상태와 로컬 추론 시간표

## 계획을 둘러싼 캐릭터 상태

로컬 3B 모델을 쓰는 GARP는 Godot의 게임 장면, 인지 계층, Rust의 추론·기억 계층을 나눈다. 캐릭터는 하루 계획을 세분화하면서 기억·감정·욕구·관계를 함께 사용한다. 성격은 대사 지시뿐 아니라 욕구 변화율과 대화 시작 확률에도 반영된다. 주변 변화는 사건으로 받아 기억과 행동 후보를 갱신한다.

행동 선택에서는 50개 이상의 후보를 보통 3~8개로 줄인다. 모델 응답은 JSON 스키마로 제한한 뒤 검증하고, 실패하면 대체 행동을 고른다. 대화는 기억 저장이 끝날 때까지 양쪽 참여자를 예약한다.

## 게임 시계가 정하는 추론 예산

저자들이 보고한 작업량은 NPC당 가상 하루에 약 130회의 채팅 호출이다. 게임 시간이 빨라질수록 한 번의 추론이 차지하는 가상 시간도 길어진다. 다음 결정을 미리 시작하고 호출·프롬프트를 줄이며 여러 단계의 캐시를 사용한다. 비동기 요청 중에도 장면은 갱신되고, 처리량이 부족하면 기존 활동을 계속한다.

## 기억한 약속이 계획에서 빠지는 실패

저자들의 9개 시나리오 반복 검사에서는 27회 중 25회가 통과했다. 생일 파티 실패는 초대 기억이 있어도 당일 계획에 반영되지 않은 경우였다. 로그상 성공과 사람이 느끼는 자연스러움은 별개이며, 후자는 평가하지 않았다.

Piero Molino 외의 [GARP v1](https://arxiv.org/html/2611.11064v1)(2026-11-08)에서 III~VIII장을 다시 읽었다. 코드 실행·기기별 처리량 검증은 하지 않았다.

# SOL-AVES와 게임 코드가 나눠 맡은 렌더링 최적화

Game Makers의 [CEDEC 취재 기사](https://gamemakers.jp/article/2026_11_06_149755/)(浜井 智史, 2026-11-06)는 엔진과 게임을 병행 개발한 과정부터 설명한다. 초기 720p·약 15fps에서 단일 화면 60fps에 도달한 사례이며, 4분할 40fps 이상은 별도의 목표였다.

## 엔진이 마련한 기반

게임이 추상적인 중간 그리기 명령을 내리면 엔진이 정렬·데이터 설정과 API 변환을 맡는다. 그 위에서 픽셀·정점·텍스처 접근 비용을 구분했다. 업스케일링과 VRS로 픽셀 비용을 줄이고, LOD와 ASTC로 다른 병목에 대응했다.

## 게임 화면에서 해상도를 조절하는 방식

부하가 커지면 내부 해상도를 즉시 낮추고 여유가 생기면 서서히 복구한다. Nintendo SDK 업스케일러를 선택한 뒤에도 HDR과 분할 경계의 보간을 따로 확인했다. 업스케일된 해상도와 최종 출력 해상도는 서로 다른 단계다.

## 해상도를 낮춘 뒤에도 남는 비용

4분할에서는 뷰마다 정점 처리와 컬링 비용이 반복된다. 팀은 가장 무거운 조건을 측정해 LOD·효과·패스 프리셋에 반영했다. 텍스처는 ASTC로 옮기되 블록 노이즈가 문제인 것은 BC 압축으로 되돌렸다.

마지막으로 조명과 가시성을 조정했다. 고부하 스테이지의 조명 선별 방식을 바꾸고 정적 가시 목록과 Hi-Z 컬링을 병용했다. DDGI는 변하지 않는 조명을 베이크한 뒤 정점이나 캐릭터 단위로 조회를 재사용했다. 이러한 선택은 정적인 날씨·시간과 스테이지 구조라는 조건에 기대고 있다.

기사 본문을 다시 읽은 기록이다. 성과는 개발팀의 보고이며 원강연 전체와 구현을 독립 검증하지 않았다.

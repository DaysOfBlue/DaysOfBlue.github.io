# 세부 카테고리 설정

기본 홈페이지와 DevBlog 미리보기에서 프로젝트·기술·취미 아래에 세부 카테고리를 표시한다. 이름과 순서는 [카테고리 설정](../content/categories.json)에서 관리하고, 글마다 frontmatter의 `category`에 해당 ID 하나를 적는다. 관리용 웹 입력 화면은 두지 않는다.

## 카테고리 추가·이름 변경

`sections`의 `projects`는 프로젝트, `tech`는 기술 공부, `hobby`는 취미 감상문에 해당한다. 배열 순서가 화면에 표시되는 순서다. 예를 들어 기술에 네트워크를 추가하려면 `tech` 배열에 다음 항목을 넣는다.

```json
{ "id": "networking", "label": "네트워크" }
```

`id`는 소문자 영문·숫자와 하이픈으로 작성한다. 같은 영역 안에서는 ID와 이름이 각각 고유해야 한다. 이름은 `label`만 바꾸면 되며 글의 `category`는 그대로 유지한다. ID를 바꾸거나 카테고리를 삭제할 때에는 해당 ID를 쓰는 글도 함께 수정한다. `all`과 `uncategorized`는 시스템 예약어이므로 설정에 넣지 않는다.

현재의 초기 분류는 다음과 같다. 이 목록은 사용자 취향이나 실제 경력을 확정한 내용이 아니며 설정 파일에서 바꿀 수 있다.

| 영역 | 초기 세부 카테고리 |
| --- | --- |
| 프로젝트 | 게임 개발, 도구 · 자동화, 웹 |
| 기술 | 렌더링, AI, 게임 엔진, 개발 도구 |
| 취미 | 독서, 게임, 영화 · 영상 |

## 글에 카테고리 지정

기술 공부 글의 frontmatter에는 다음처럼 등록된 ID를 쓴다.

```yaml
type: study
category: rendering
```

프로젝트는 `projects`, 기술 공부는 `tech`, 감상문은 `hobby`에 등록한 ID만 사용할 수 있다. 한 글에는 한 카테고리만 지정한다. `category`를 생략하면 미분류로 표시한다. 소개/CV에는 카테고리를 지정하지 않는다. 본문 목차나 글의 종류·공개 경로는 바뀌지 않는다.

기존 공개 기술 글 21편에는 본문의 중심 주제를 기준으로 카테고리를 지정했다. 렌더링 8편, AI 8편, 게임 엔진 1편, 개발 도구 4편이다. AI를 사용하는 렌더링 글처럼 주제가 겹칠 수 있으므로 탐색을 위한 편집상의 분류로 취급한다. 본문과 출처는 변경하지 않았다. 프로젝트와 취미에는 공개 글이 없어 글 수가 0으로 표시된다.

## 화면과 빌드

- 메인 탭 아래와 각 분야 목록에 카테고리 이름과 글 수를 표시한다. 개수는 메인의 최신 5개가 아닌 해당 분야의 전체 공개 글을 기준으로 센다.
- 카테고리를 선택하면 해당 분야의 정적 목록 페이지로 이동한다. 기본 홈페이지의 예는 `/tech/categories/rendering/`이며 미리보기에는 `/preview/devblog` 접두사가 붙는다. 해당 카테고리의 공개 글 전체를 최신순으로 표시한다.
- 전체를 선택하면 분야 전체 목록으로 이동한다. 글이 없는 설정 카테고리도 표시하며, 미분류는 해당 공개 글이 있을 때만 표시한다.
- 목록의 카테고리명과 상세 글 위의 분류 링크에서도 같은 카테고리로 이동할 수 있다. JavaScript가 없어도 카테고리 링크와 목록은 사용할 수 있다.

수정 후 아래 명령으로 검사·재생성하고 브라우저를 새로 고침한다.

```powershell
npm run check
npm run build
```

서버가 꺼져 있으면 `npm run dev`로 실행하고 [로컬 홈페이지](http://127.0.0.1:4173/)를 연다. 미등록 ID, 다른 분야의 ID, 잘못된 설정은 검사와 빌드에서 오류로 알린다. 초안의 카테고리도 구조 검사의 대상이지만 목록과 글 수에는 공개 목록의 문서만 반영한다. 설정 JSON이나 초안 파일을 웹에 복사하지 않는다.

별도 비교 화면을 다시 만들 때에는 `npm run build:preview`를 사용한다. 기본 홈페이지와 미리보기는 같은 설정을 읽으며 출력 폴더와 URL 경로를 구분한다.

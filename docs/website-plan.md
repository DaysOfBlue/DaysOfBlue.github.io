# 포트폴리오 홈페이지 구성

홈 상단에서 자기소개를 보고 프로젝트·기술·취미를 각각 탐색한다. DevBlog 기반의 회색 디자인과 Noto Sans KR을 기본 홈페이지에 적용한다. 작은 썸네일을 둔 한 줄 목록을 사용하며 대표 프로젝트 영역과 이메일 구독 폼은 두지 않는다. 자료 모음의 주제로 사용자의 직업이나 경력을 추정하지 않는다.

구현은 Node.js 내장 모듈과 일반 HTML을 사용한다. 외부 패키지나 웹 프레임워크를 추가하지 않는다. 로컬 빌드와 편집 기능을 제공하며 호스팅·도메인·배포는 별도 작업이다.

## 페이지와 역할

| 경로 | 역할 | 담을 내용 |
| --- | --- | --- |
| `/` | 자기소개와 분야별 미리보기 | 자기소개 요약과 프로젝트·기술·취미 전환 목록 |
| `/about/` | 작성자와 공개 이력 확인 | 공개 프로필 본문 또는 빈 CV 양식 |
| `/projects/` | 프로젝트 탐색 | 공개 프로젝트 목록과 세부 카테고리 |
| `/projects/<slug>/` | 실제 작업과 기여 설명 | 문제, 본인 역할, 접근과 선택 이유, 결과·검증 근거, 한계 |
| `/tech/` | 기술 공부 탐색 | 기술 공부 목록과 세부 카테고리 |
| `/study/` | 기술 공부 전체 목록 | 작성일순 학습·실험 글 |
| `/study/<slug>/` | 학습 내용과 확인 범위 공유 | 글마다 구성한 기술 글, 첨부와 출처 |
| `/hobby/` | 취미 감상문 탐색 | 감상문 목록과 세부 카테고리 |
| `/reviews/` | 취미 감상문 전체 목록 | 작성일순 감상문 |
| `/reviews/<slug>/` | 작품·활동에 대한 감상 공유 | 확인한 원작과 사용자의 실제 감상에 맞춰 구성한 글 |
| `/<분야>/categories/<id>/` | 분야별 분류 탐색 | 해당 카테고리의 전체 공개 글 |

카테고리 경로의 분야는 `projects`, `tech`, `hobby` 중 하나다. 글 상세는 공개 목록에 등록한 문서가 있을 때만 생성한다. 각 글은 소속 목록으로 돌아가는 링크를 제공한다. 서로 관련된 글은 본문에서 연결할 수 있지만 다른 분야의 목록에 섞어 표시하지 않는다.

## 홈에서 읽는 순서

1. 자기소개를 본문의 첫 영역에 둔다. 공개 프로필의 `summary`만 표시하며 요약이 없으면 소개 페이지로 안내한다. 프로필이 미공개이면 준비 중 안내를 표시한다.
2. 프로젝트·기술·취미 탭에서 분야를 선택한다. 기본 선택은 프로젝트이며 주소 해시로 선택한 분야를 다시 열 수 있다.
3. 각 분야의 글을 `created` 최신순으로 최대 5개 표시하고 독립 목록과 카테고리로 연결한다. 카테고리의 개수는 전체 공개 글을 기준으로 센다.

메인에는 CV 전체나 별도의 대표 프로젝트 묶음을 표시하지 않는다. `featured`는 호환 메타데이터로만 유지한다. 수정일을 새 작성일처럼 취급하지 않는다.

## 공통 구조와 이동

메뉴는 홈·소개·프로젝트·기술·취미 순서다. 프로젝트 상세는 프로젝트, 공부 상세는 기술, 감상문 상세는 취미에 속한다. 본문으로 바로 이동하는 링크와 의미 있는 제목 구조를 제공한다.

페이지 이동은 일반 링크를 사용한다. 홈 전환은 탭 역할과 선택 상태를 제공하며 클릭과 방향키·Home·End·Enter·Space로 조작한다. JavaScript가 없으면 세 영역을 모두 표시하고 앵커 링크로 이동한다. 작은 화면에서는 사이드바를 메뉴 버튼으로 전환한다. 탭의 역할과 키보드 동작은 [WAI 탭 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)을 참고한다.

## 프로젝트·공부·감상문의 작성 방식

프로젝트 글에는 문제와 맥락, 본인이 맡은 범위, 접근과 선택 이유, 결과와 검증 근거, 한계를 담는다. 본인의 기여와 팀 전체 결과를 구분하고 성과 수치에는 측정 조건이나 원자료를 연결한다. 빈 경력이나 성과를 자동으로 채우는 양식으로 사용하지 않는다.

기술 공부는 실제로 읽은 원문의 목차·논증·설명 흐름을 파악해 글마다 구성한다. 고정 목차나 같은 소제목을 반복하도록 요구하지 않는다. 프로젝트에서 배운 점은 연결할 수 있지만 공부 글 자체는 독립해서 관리한다.

취미 감상문은 확인한 원작·원문과 사용자가 제공한 감상에 맞춰 전개한다. 작품의 사실 정보를 확인하고 사용자의 경험과 목소리를 보존한다. 느낌을 대신 만들지 않으며 필요한 경우 내용 누설 여부를 알린다.

Markdown 이미지, 영상·YouTube 블록과 게시물별 표시 설정을 지원한다. 공개용 출처가 있으면 글 하단에 표시한다. 본문 중 근거를 설명하는 링크는 유지하며 별도 출처 절이나 특정 본문 목차를 강제하지 않는다. [편집 안내](media-authoring.md)를 참고한다.

## 현재 콘텐츠와 소개

기술 공부 글 21편과 하단 출처 28개를 기본 홈페이지에 표시한다. 기존 Markdown은 보존하고 대조한 말미 출처 문구만 화면에서 중복 표시하지 않는다. 프로젝트와 취미 감상문에는 아직 공개한 문서가 없고 소개와 프로젝트 초안은 `draft`다.

공개 프로필이 없으므로 메인은 준비 중 안내, 소개는 빈 CV 양식을 표시한다. 이름·이력·연락처는 확인한 실제 정보가 제공되면 작성하고 검토 후 등록한다. [CV 작성 안내](cv-authoring.md)에 참고 글의 대학원 지원 맥락과 개인 홈페이지 적용 범위를 구분했다. 가상의 작품이나 수치로 빈 공간을 채우지 않는다.

## 저장소와 출력 경계

`raw/`는 원자료, `wiki/`는 근거를 연결한 분석과 내부 결정을 보관한다. 방문자용 문서는 `content/`에서 편집하며 [콘텐츠 규약](content-model.md)에 따라 검토한다.

기본 빌드는 `content/manifest.json`에 등록된 `reviewed`, `visibility: public` 문서와 지정한 정적 자산, 공개 글이 참조한 첨부만 `dist/`에 출력한다. 원자료·wiki·미등록 초안·편집용 JSON·편집기 코드와 기능 예제는 복사하지 않는다. 내부 경로나 원자료 ID도 자동으로 공개하지 않는다.

기본 홈페이지에는 미리보기 표시·글꼴 비교 막대·`noindex`를 넣지 않는다. 비교 버튼과 미디어 예제는 별도 `/preview/devblog/` 화면에 유지한다. 기본 홈페이지와 미리보기 모두 DevBlog 제작자 링크를 유지한다. [디자인 안내](design-preview.md)에 자산과 이용 조건을 정리했다.

| 명령 | 용도 |
| --- | --- |
| `npm run build` | 구조 검사 후 기본 홈페이지 생성 |
| `npm run dev` | 4173 포트에서 기본 홈페이지 확인 |
| `npm run edit` | 4175 포트에서 첨부·출처 편집. 저장하면 기본 홈페이지 재생성 |
| `npm run dev:preview` | 4174 포트에서 별도 비교용 화면 확인 |
| `npm run edit:preview` | 4176 포트에서 별도 미리보기와 예제 편집 |
| `npm run check`, `npm test` | 저장소 구조와 렌더링·공개 경계 검사 |
| `npm run check:sources` | 등록된 원자료의 존재와 해시까지 검사 |

실제 정보가 준비되면 소개·프로젝트·감상문을 검토하고 공개 목록에 등록한다. 빌드·테스트와 화면 검토는 수행한 범위대로 작업 로그에 기록한다. GitHub push, 배포와 도메인 연결은 명시적인 요청 전에는 수행하지 않는다.

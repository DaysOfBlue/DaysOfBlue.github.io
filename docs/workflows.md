# 운영 절차

## 원자료 수집

1. 원본을 `raw/`에 새 이름으로 저장하고 SHA-256을 계산한다. 기존 원문은 덮어쓰지 않는다.
2. `raw/manifest.json`에 새 출처 ID를 등록한다. 입수일은 등록한 한국시간 날짜다. 작성자·발행일·URL이 없으면 `null`로 둔다.
3. 원문을 읽고 [출처 템플릿](../templates/source.md)을 복사해 `wiki/sources/` 요약을 만든다. 외부 링크만 읽었거나 이미지·부록을 확인하지 않았다면 범위를 남긴다.
4. 원문이 말한 것과 프로젝트에 적용한 해석을 구분한다. 다른 기록과 충돌하면 근거를 나란히 기록한다.
5. 관련 페이지와 [인덱스](../wiki/index.md)를 갱신하고 목록을 `ingested`로 바꾼다. [로그](../wiki/log.md)에 변경 파일과 미해결 사항을 추가한다.
6. `npm run check:sources`를 실행한다. 원자료가 없는 clone에서는 `npm run check`로 구조를 점검하되 원본 검증 누락을 보고한다.

여러 자료를 한 번에 넣어도 각 출처의 처리 상태를 따로 기록한다. 게임 개발·AI 자료 모음은 `raw/game-ai/`에 저장한다. 기존 모음 7개는 출처 탐색 자료로 읽었고, 연결된 웹 원문은 별도 보관했다. 원문을 읽지 않은 자료는 `pending`으로 남긴다. [수집 결과](game-ai-ingestion.md)에 실제 독해 범위와 제한을 기록했다.

## 질문을 지식으로 남기기

인덱스에서 관련 페이지를 찾고 필요한 원문을 확인한다. 답변의 근거와 한계를 적는다. 나중에도 사용할 분석이면 기존 페이지에 반영하거나 새 페이지를 만든 뒤 인덱스·로그를 갱신한다. 질문 자체가 경험이나 사실의 증거가 되지는 않는다.

## 홈페이지 글로 편집하기

프로젝트는 [프로젝트 템플릿](../templates/publication.md)을 사용할 수 있다. 본인 역할과 팀 결과를 구분하고 실제 산출물이나 측정 근거를 확인한다.

기술 공부·감상문은 본문 템플릿을 사용하지 않는다. 보관한 실제 원문을 읽고 그 글의 목차·논증·설명 흐름을 확인한 다음, 각 원문에 맞는 구성을 정해 빈 문서에서 작성한다. 같은 소제목과 순서를 반복하는 대체 양식도 만들지 않는다. 필요한 게시 메타데이터만 [콘텐츠 규약](content-model.md)에 맞춘다.

감상문은 실제 확인한 원작·원문과 사용자의 감상에 맞춰 서술한다. 사용자의 목소리를 보존하고 사실 정보와 개인적인 느낌을 구분한다. 원문이나 원작을 확인하지 못했다면 그 범위를 밝히고 부족한 내용을 꾸며내지 않는다.

본문과 출처를 대조하고 미작성 항목을 해결한 후 `reviewed`로 바꾼다. 감상문의 출처로는 사용자의 원본 메모를 사용할 수 있다. 공개 가능한 글만 `content/manifest.json`에 등록한다. 프로젝트는 `/projects/<slug>`, 기술 공부는 `/study/<slug>`, 취미 감상문은 `/reviews/<slug>`, 소개는 `/about` 경로를 사용한다. 대표 프로젝트에는 `featured: true`를 지정한다.

출처 링크와 확인 범위는 해당 설명 곁이나 글 말미에 적는다. 별도 출처 절이나 특정 소제목을 요구하지 않는다. 원문을 따르는 구성은 전문 복제·번역을 뜻하지 않는다.

`npm run build`로 생성하고 `npm run dev`로 목록·상세·소개를 확인한다. 이미 서버가 실행 중이면 빌드 후 브라우저를 새로 고침한다. 자세한 구성은 [홈페이지 계획](website-plan.md)에 있다. 이 과정에 원격 배포는 포함하지 않는다.

## 정기 점검

기계 검사 후 관련 문서를 직접 읽으며 다음을 확인한다.

- 새 자료가 이전 주장을 반박하거나 갱신하는가?
- 성과 수치의 측정 조건, 역할, 날짜가 충분한가?
- 인덱스 외에 관련 페이지에서도 유용한 연결을 찾을 수 있는가?
- 근거 없는 확신, 중복 페이지, 오래된 미결정 사항이 남아 있는가?
- 공개 글에 비공개 정보나 재배포할 수 없는 자료가 들어갔는가?

해결한 내용과 남은 질문을 로그에 추가한다. 링크 검사 통과를 사실 검증 완료로 표현하지 않는다.

## 검증 명령의 범위

`npm run check`는 문서 링크 대상의 존재, 필수 메타데이터와 출처 연결, 인덱스 등록, 로그 날짜 순서, 공개 목록의 상태·경로, 존재하는 원본 해시를 검사한다. Markdown 앵커의 정확성과 외부 URL의 응답은 검사하지 않는다.

`npm run check:sources`는 여기에 원본 파일의 존재를 필수로 요구한다. 두 구조 검사 명령은 사실성, 문장 간 모순, 개인정보 전체, 렌더링이나 접근성을 판정하지 않는다.

`npm test`는 Markdown 렌더링과 공개 대상 경계, 목록·상세 연결과 로컬 HTTP 동작을 검사한다. `npm run build`는 구조 검사 후 공개 문서를 렌더링하고 기존 `dist/`를 교체한다. 실제 화면과 키보드 이동은 필요한 범위에서 브라우저로 별도 확인한다.

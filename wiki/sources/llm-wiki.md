# LLM Wiki 인사이트

## 원문과 확인 범위

사용자가 붙여넣은 [원문](../../raw/llm-wiki.txt)을 읽었다. 출처 ID는 `src-llm-wiki`이며 2026-11-18에 등록했다. 문서에 확인 가능한 작성자와 발행일이 없어 목록에는 `null`로 기록했다. 외부 링크의 본문, 제품별 현재 기능, 비용·효과는 별도로 검증하지 않았다.

## 원문이 제안하는 방식

원자료를 질문마다 다시 조합하는 대신, 에이전트가 지속적으로 갱신하는 Markdown wiki를 중간 산출물로 유지한다. 원문은 원자료·wiki·작업 규약의 세 층을 구분한다.

자료를 넣을 때 요약뿐 아니라 관련 개념과 기존 문서의 연결을 갱신한다. 질문으로 얻은 재사용 가능한 분석도 지식에 반영한다. 주기적으로 모순, 오래된 주장, 연결이 부족한 페이지, 빠진 근거를 찾는다.

`index.md`는 내용을 찾는 목록, `log.md`는 작업을 추적하는 날짜순 기록이다. 규모가 작을 때는 문서와 인덱스로 시작하고 검색 도구는 필요할 때 추가할 수 있다는 제안이다.

## 이 프로젝트에 적용한 해석

포트폴리오는 원문·학습 기록 전체와 공개 글의 독자가 다르므로 `content/`를 별도로 두었다. 공개 목록으로 홈페이지 입력을 제한하고, 외부 자료를 개인 경력의 증거로 바꾸지 않는 규칙을 추가했다.

## 한계와 비판적 검토

에이전트도 연결을 빠뜨리고 잘못 요약하거나 기존 문서를 모순되게 바꿀 수 있으므로, 원문의 일부 표현을 검증 없이 운영 보장으로 받아들이기 어렵다. 유지 비용이 거의 없어진다는 주장도 이 프로젝트에서 측정하지 않았다. 검사와 사람이 읽는 검토가 필요하다.

원문이 기존 RAG 방식에 관해 내린 일반화나 제품 기능 설명을 이 저장소의 사실로 채택하지 않았다. 여기서는 누적 wiki라는 설계 패턴을 사용한다. 특정 검색 도구, Obsidian 플러그인, 벡터 검색은 설치하지 않았다.
